# 多CFD算例并行计算

## 使用

1. 打开CFD工作台，连接计算服务。
2. 在“计算槽位”选择“同时运行”数量并点击应用。当前本机可设置1–8，默认2。
3. 输入可选算例名称，选择模板、设计和工况，点击提交。
4. 修改名称或工况后继续提交：有空闲槽位则并行执行，否则按提交顺序等待。
5. 任务下拉框显示名称、状态和当前阶段。工作台每2.5秒刷新，包括当前选中任务已经结束的情况。可切换查看每个算例的残差、日志及结果。

这是独立case级并行，每个case仍按顺序执行几何、网格、检查、求解和打包；没有启用单个case的MPI分域。

## 配置

从仓库根目录：

```bash
bash scripts/start.sh --max-parallel 2 --max-pending 16 --case-threads 1
```

- `--max-parallel`：同时占用执行槽位的算例数，默认2。受`min(8, CPU数/case_threads, max_pending)`约束。
- `--max-pending`：运行、取消中和排队任务的总上限，默认16，最大64；不是仅排队数量。
- `--case-threads`：子进程的OMP/OpenBLAS/MKL/NumExpr线程设置，默认1。不是MPI进程数；具体工具是否使用这些线程由工具自身决定。
- `--timeout`：每个case获得槽位后的执行超时设置，默认7200秒；排队等待不消耗该计时。

内存没有自动估算/排程。不同网格大小的任务共用同一并发上限，默认2用于保守启动。网页修改在当前服务进程内生效，重启后采用启动参数。

## 调度语义

- 全流程占用槽位，包含准备、网格、求解和打包。
- 增大并发数会唤醒排队任务；减小并发数不会终止正在运行的任务，直到运行数低于新上限才启动下一项。
- 取消排队任务会立即释放排队名额；取消运行任务只终止该任务进程组，其余case继续。准备几何时可能短暂显示“正在停止”，槽位保留至该任务实际退出。
- 失败、取消或超时后释放槽位，后续case可以继续。
- 每个任务有独立UUID目录、请求快照、日志和结果包。不会共享可变的case工作目录，也不在任务之间修改全局工作目录或环境。
- 服务优雅停止时取消自身未完成任务；重启后保留历史记录并将未完成任务标记为中断，不静默恢复。
- 并行机制用于一个计算服务进程；不要让多个服务同时管理同一个jobs目录。

## API

所有接口均要求已有Bearer令牌和允许的Origin。

- `GET /api/scheduler`：返回并发配置、运行/排队数量和容量。
- `POST /api/scheduler`，JSON `{"max_parallel":2}`：动态调整并发数；拒绝其他字段、非整数和越界值。
- `GET /api/health` 与 `GET /api/jobs` 同步提供调度状态。
- `POST /api/jobs` 增加可选 `name`（最长80字）。达到总任务上限返回HTTP 429，不接受超额任务。
- 各任务响应增加 `started_at`、`ended_at` 和 `stage_history`。阶段记录含PID、开始/结束时间与退出码，表示历史执行证据。

## 真实并行验证（2026-09-12）

两套Pritchard二维叶栅分别使用入口总压100200与100300 Pa，各运行300步，采用不同工作目录与求解PID。两个rhoSimpleFoam进程的执行时间实际重叠约 **9.089 秒**；各自完成网格检查、求解、VTK及ZIP导出。归档参数与各自提交的工况一致，ZIP完整性检查通过。

这次短算例验证的是并发执行与数据隔离，两次300步运行均未确认收敛，不作为新的气动验证结论。[可追溯阶段与结果包摘要](data/parallel-validation.json)

进程夹具回归测试进一步检查排队上限、取消隔离和动态并发行为；夹具结果不是CFD物理结果。运行全套检查：`bash scripts/check.sh`。
