# AeroBlade 对话初设与设计优化平台方案

日期：2026-09-18。当前实施范围：对话初始界面、模型 API 适配接口、参数确认与现有设计页交接。其余阶段为后续规划。

## 1. 产品流程与信息架构

推荐将“初始设计”“叶片设计”“性能评估与优化”“CFD 仿真”作为最终四个工作区。初始设计只提供对话交互，生成后的只读方案卡也属于对话；参数编辑集中在叶片设计。当前已存在 AI 预测工作区，第一期保留，不将未开发的评估与优化伪装为可用页面。

相比把参数表和聊天并排放在首页，对话入口更符合总体要求逐步澄清的工作方式。相比强制线性向导，允许跳过对话可兼容专家已有参数、参考截面及导入数据。本方案采用对话主入口与自由工作区切换结合。

完整业务顺序：总体需求 → 约束澄清 → 一维/平均线求解及参数建议 → 审阅初始方案 → 二维截面参数化 → AI/CFD 并行评估 → 优化候选与 CFD 复核 → 径向多截面积叠 → 三维 CFD 与验证。三维几何需要在三维评估之前建立；三维验证不能只放到全部优化结束后，后续应允许回到多截面优化。

## 2. 总师智能体的职责与依据

智能体收集流量、功率、效率目标、转速、入口总温/总压、出口压力或压比、工质、流路尺寸约束、转/静子与设计半径、级数限制。缺少的条件通过对话追问；用户明确允许的假设记录在方案中。单凭流量、功率、效率一般不能唯一确定级数、流路和速度三角形。

大模型负责组织要求、调用工具、解释方案和提出有依据的候选；数值守恒、速度三角形、损失/落后角关联由版本化平均线求解器处理。未来记录求解器版本、参考设计、经验关联、适用工况、单位、角度定义及每个参数来源。未接平均线求解器时，模型输出只能标记为初设建议，不能称为求解收敛结果。

初始化严格沿用项目 `aeroblade/docs/PRITCHARD.md` 和 `web/pritchard.js`：R、N、Cx、Ct、O、RLE、RTE、βin、βout、εin、UGT。长度 mm，角度 deg，x 轴为轴向，出口采用当前内核支持的负角分支，进口楔角为半角。height 为额外拉伸展示设置，不属于 11 参数。安装角、节距、出口半楔角为派生量。气流角与金属角分开存储，转子相对角与静子绝对角也须标注。调研中的正出口角范围或其他楔角命名不得直接映射到本内核。

不将“六个默认值”或未经核对的区间固化为普适工程规律。参考初值复用图19预设并注明其尺度只是软件选择；未来以相似工况数据库/平均线结果初始化，校验喉道、节距和轮廓组合。几何校验通过不代表气动目标满足。

## 3. 初始界面与交互

- 首屏为居中的总师智能体欢迎区、三条可编辑的示例需求、对话输入框、模型来源选择，以及始终可用的“跳过对话，手动设计”。不放几何滑块、仿真表单或性能仪表盘。
- 默认提供明确标识的参考演示；通用模型、航发领域模型由同源 API 分流。未连接时提示接口尚未接入，可重试或选择演示。演示不会解析任意要求并伪造推导；只有显式“载入参考方案”操作返回原图19预设。
- Enter 发送，Shift+Enter 换行，中文输入法组合期间不发送；空白与超长输入禁止。支持发送中、停止、错误、重试、继续补充、重新开始。
- 方案卡显示版本、来源、几何校验状态、关键气动参数及其来源、全部11参数、展示展宽、假设与待验证项。气动参数无数据时显示尚未计算。不给参考演示编造气动性能。
- 只有字段/单位/参数来源齐全、无待补条件且实际几何内核验证通过的方案才显示可用确认动作。每次继续对话或切换来源立即使旧方案不可应用，避免新需求与旧初值错配。
- 用户确认“采用此方案并进入叶片设计”后，完整参数原子交给已有 `applyDesign` 入口；成功后切页。应用失败留在首页说明原因。手动入口只切页，不改当前设计。
- 会话与输入草稿存入 sessionStorage，刷新后恢复并重新验证方案。重载时未完成请求标为中断并可重试。应用状态不持久化为“已同步”，因为现有设计页刷新会重新载入基准参数。会话新建需要用户确认清除；存储不可用时仍可对话。
- 使用 textContent 输出模型文本，不执行模型 HTML。对话记录长度有上限，API 密钥放服务端，浏览器仅调用同源接口。导航具备选中态、键盘切换与正确隐藏行为。
- 全部工作区共用顶部白色栏、标题字号和导航布局，保留“导入参数”“导出设计”全局动作，操作对象为当前叶片设计。初始设计不另行覆盖顶部栏高度或隐藏按钮，切换时位置保持一致。

## 4. 性能评估与优化工作区（后续）

建议同页分成“单方案评估”“优化任务”“候选对比”三个子页签，共用被冻结的 designRevision、conditionRevision 和 geometryHash。左栏选设计版本/工况与评价目标，中部显示曲线或流场，右栏显示指标、来源和可信状态。AI 与 CFD 为同级评估来源，可独立运行、并行提交或对照；AI结果先返回不应覆盖 CFD 结果。

单方案评估：同一几何/工况下并排展示 AI 预测与 CFD 结果、误差、耗时、模型适用域、CFD 收敛与网格质量。二维静止冷态叶栅优先使用现有总压损失、出口流角、转折、单位展宽质量流量和载荷指标；整级效率及轴功率必须有相应级/转子模型才启用。

优化任务：选择11参数中的设计变量与边界、固定变量、目标、约束、预算、DOE/优化方法与停止条件。先通过几何过滤，再用代理模型筛选，再提交 CFD 复核；保留纯 CFD 路线。显示队列、可行率、目标收敛、预算与暂停/继续/终止。无效几何不提交求解，失败任务单独记录并支持重试。

候选对比：参数变化、目标指标、约束裕度、Pareto 前沿和证据来源；支持挑选候选回到叶片设计。只有已实际 CFD 评估且通过质量检查的结果标记为已复核，AI 最优不自动成为最终设计。第一阶段完全不包含 FEA、热应力或多学科指标。

## 5. CFD 三维模板（后续新开发）

新模板建议 ID `pritchard-radial-stack-3d`，区别现有二维周期模板及有限展宽端壁探索。输入叶根/中径/叶尖及可增加的径向站位、各站11参数、积叠线、扭转/弯掠、轮毂/机匣、叶顶间隙、叶片数、转/静子框架及工况。

实现站位单调性与相邻截面检查、圆柱映射、光滑放样、周期扇区、端壁与间隙网格、转动参考系配置、网格质量检查、残差/守恒/性能监控与网格无关性评估。局部二维展开截面不能直接当作完整环形转子。明确是否建级间接口、冷却或多排叶栅；第一版范围优先单叶排，进一步级模型另立模板。

验收分为几何、网格、求解收敛、质量/能量守恒、网格敏感性、参考或试验对比；已有三维探索尚未收敛，不继承其验证结论。

## 6. 第一阶段文件边界和验收

新增 `web/design-assistant-client.js`（协议、演示、校验、HTTP）、`web/design-assistant.js`（对话状态与UI）、`web/design-assistant.css`；在 `cfd.js` 的既有导航注册初设工作区，复用 `app.js` 已有应用参数回调；`index.html` 加载样式。不改几何公式、CFD 求解逻辑或 AI 模型训练功能。

验收：首次打开首页；参考方案成功校验并传入11参数；手动入口不覆盖设计；返回首页保留对话；新要求使旧方案失效；停止/重试无迟到响应；模型响应格式错误、网络失败、缺字段、非法几何不会覆盖设计；刷新恢复；移动端与键盘可用；项目回归及发布包通过。
