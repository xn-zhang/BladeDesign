# 批量叶片设计、CFD生产批次与AI训练数据

三个入口已接通：**初始设计 → 批量方案**、**CFD仿真 → 批次仿真**、**AI预测 → 数据与训练 → 按CFD批次构建训练数据集**。

## 一次完整操作

1. 在初始设计对话中取得有效方案，或在叶片设计页准备基准。点击初始设计顶部“批量方案”。如果当前对话有有效初设，优先使用该初设；否则使用当前叶片。
2. 填写批次名称，选择1–6个变化变量及包含基准值的上下界。其余参数保持基准值。默认12组几何（含基准）、随机种子42，以及入口总压100200/100300/100400 Pa的3个冷态工况，共36个候选算例。
3. 可展开“让总师智能体建议采样方案”，选择通用或航发领域模型，输入目标后获取建议。调用已有真实模型配置；返回的范围、数量、工况和理由会填入表单。服务不允许模型修改基准参数，也不接受性能数值作为训练标签。建议必须由几何内核继续检查。
4. 点击“生成并校验参数”。后台按固定种子采样，调用实际Pritchard几何内核，剔除无效和重复几何，有限补采样。检查有效数量、未补足数量、轮廓缩略图和拒绝原因。
5. 点击“发送到CFD批次”。此操作只保存待启动批次。也可导出JSON，在CFD的批次页面导入；导入会重新检查所有几何、工况和单位，相同已保存参数会复用原包，防止反复导入生成重复生产批次。
6. 在CFD批次页核对算例总数、在途上限和后端就绪状态，再点击“启动/继续”。每个“几何×工况”组合分别生成网格和求解。页面显示几何ID、工况ID、尝试次数、CFD状态、质检状态及任务ID。
7. 批次结束后点击“到AI构建数据集”。在独立AI工作区选择生产批次，点击“检查并构建数据集”。只检查该批次的最新尝试，通过后自动选中新数据版本；随后选择Ridge/ExtraTrees/MLP训练。

平台当前只支持二维冷态Pritchard生产批次。建议先验证小批量网格成功率、收敛率和质量检查，再扩大采样范围。多个工况不会增加独立几何数量，12组几何仍是实验性训练规模。

## 范围与结果含义

- 几何最多300组、工况最多10组、组合最多1000个；每次批次最多8个在途任务，实际并发由CFD manager的全局计算槽位决定。
- 当前模板支持入口总压100100–100500 Pa、入口总温290–310 K、出口静压100000 Pa、迭代上限100–5000；这些是当前冷态模板的软件范围，不是发动机通用工况范围。
- height只控制三维展示，不作为本批次的采样变量。角度仍使用轴向有符号角、负出口角及进口半楔角。
- 采样包含基准，使用分层DOE并经几何拒绝/补采样；筛选后的点不保证仍满足严格LHS分层。补采样最多为目标数量10倍，最高3000次。未补足会明确报告，不能把“目标12组”当成已经生成12组。
- “CFD完成”仅表示求解进程完成。“质量通过”来自后续收敛、守恒、网格和边界场检查。收敛但性能一般的样本也会保留，数据不按性能优劣筛选。

## 暂停、恢复、重试

- 暂停：停止补充新任务，已提交CFD继续执行。
- 取消：仅取消本批次未提交和仍运行的任务，保留已完成结果和诊断；不停止其他批次或单算例。
- 重试：先暂停，勾选失败、取消、中断或质检拒收的已结束算例。选择“重试选中失败项”后，再点“启动/继续”。历史任务ID保留，新尝试使用新的提交标识。
- 队列满：等待空位，不把算例直接判失败。
- 请求响应不确定：停止补充队列，按持久提交键核对已有任务，继续时复用已创建任务。
- 服务重启：生产批次转为暂停，不自动重新发起整个批次。已有任务状态由manager恢复或标记中断，用户核对后选择继续/重试。
- 同一提交键不能用于不同参数、工况或批次。即使任务完成后重复请求，也返回原任务，不能重复求解。

## 数据和版本追溯

生成包包含基准、变量范围、随机种子、来源说明、所有有效参数、工况、几何摘要和拒绝记录。每批首次启动时复制独立模板，记录模板摘要。之后提交和重试使用这个副本；副本被修改后停止继续提交。

数据集记录 batch_id、batch_case_id、geometry_id、condition_id、真实job_id、源文件摘要和质量报告。每个算例只扫描最新一次尝试，早期失败或被替代结果不会自动混入新数据版本。

默认要求批次所有算例结束后构建。勾选“允许使用已结束的部分结果”时，只扫描已结束任务，同时记录未纳入算例。不同批次和不同模板不会因一次批次扫描被混入；训练器仍要求模板与热物性一致。相同几何的多个工况按几何组共同分配训练/验证/测试集。

存储位于 `--evaluation-dir`（默认 `aeroblade/ai-data`）：

```text
design-batches/<参数包ID>/manifest.json
batches/<批次ID>/batch.json
batches/<批次ID>/template/
tasks/<任务ID>/task.json
datasets/<数据版本ID>/manifest.json
datasets/<数据版本ID>/samples/*.npz
```

CFD原始文件仍在 `--jobs`。批次、评估和训练使用同一个后端及任务目录。单算例页面连接的另一台独立CFD服务器不会自动成为批次后端；远程部署时应在求解机运行这套完整bridge，并将网页同源API转发到它。

model-only可以请求大模型建议、生成/导入参数、保存批次以及检查已有CFD。真实批次仿真需要完整OpenFOAM环境。数据/计算代码变更会触发模型版本校验，旧模型可能需要在AI页面重新训练。

## API

接口沿用登录会话、CSRF和允许来源规则，不需要在同源网页填写额外平台令牌。

| 路由 | 内容 |
|---|---|
| POST `/api/design-assistant/batch-plan` | `{provider,instruction,plan}`；返回可审阅建议，不提交CFD |
| POST `/api/evaluation/batch_generate` | `{plan:{name,baseline,bounds,count,seed,conditions,provenance?}}`；返回后台任务 |
| POST `/api/evaluation/batch_import` | `{bundle}`；完整重校验参数包 |
| GET `/api/batches/designs` | 参数包列表 |
| GET `/api/batches/designs/<id>` | 参数包 |
| POST `/api/batches` | `{design_batch_id}`；保存/复用待启动批次 |
| GET `/api/batches`、`/api/batches/<id>` | 批次列表、详情与算例追溯 |
| POST `/api/batches/<id>/start`、`resume` | `{max_in_flight?:2}` |
| POST `/api/batches/<id>/pause`、`cancel` | `{}` |
| POST `/api/batches/<id>/retry` | `{case_ids:[...]}` |
| POST `/api/evaluation/dataset` | `{batch_id,allow_partial:false}`；服务端冻结选择，不接受客户端指定任意任务清单 |

大模型服务契约、任务调度和数值提取分别有隔离测试。历史真实CFD可用于只读回放验收，但不表示本轮运行了新的OpenFOAM算例；测试目录与正式目录分开。
